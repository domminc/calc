# 디자인 정의서

> **v2 (2026-10 리디자인)가 현재 기준이다.** 아래 §10 "v2 디자인 시스템"이 §2~§4 의 색·컴포넌트·화면 구성보다 우선한다. §1 원칙, §6 접근성, §9 폰트는 그대로 유효하다.

> 대문 사이트(`homesell.co.kr`)의 톤을 계승한다: **차분한 에디토리얼 타이포 + 헤어라인 카드 + 단일 포인트 컬러(초록)**, 라이트/다크 자동.
> 구현 CSS는 `public/css/app.css` (이 문서의 토큰이 그대로 `:root`에 들어간다).

## 1. 디자인 원칙
1. **숫자가 주인공**: 결과 숫자(월 실수령)를 화면에서 가장 크고 진하게. 나머지는 보조.
2. **근거가 보이게**: 모든 공제 항목은 요율·기준일을 한 줄로 설명(툴팁이 아니라 표 안에 상시 노출).
3. **입력은 최소, 결과는 즉시**: 기본값이 채워져 있어 첫 화면에서 이미 결과가 보인다.
4. **모바일 우선**: 360px에서 완결. 엄지 영역에 주요 입력, 결과 요약 하단 고정.
5. **색에만 의존하지 않기**: 차트 구간은 색 + 직접 라벨 + 표.

### 2.2 타이포그래피
- 글꼴: **Pretendard Variable** (다이나믹 서브셋, 자체 호스팅). 폴백 `system-ui, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`.
- `html { word-break: keep-all; overflow-wrap: break-word; }` 한글 어절 보존.
- 숫자는 `font-variant-numeric: tabular-nums` (표·결과 정렬).

| 역할 | 크기 / 굵기 / 자간 |
|---|---|
| 결과 히어로 숫자 | `clamp(2.25rem, 8vw, 3.5rem)` / 700 / -0.035em |
| H1 | `clamp(1.625rem, 4vw, 2.25rem)` / 700 / -0.03em |
| H2 | 1.25rem / 700 / -0.025em |
| 본문 | 1rem / 400 / -0.01em, line-height 1.65 |
| 표·라벨 | 0.9375rem / 500 |
| 보조·각주 | 0.8125rem / 400 |

### 2.3 간격·형태·그림자
- 간격 4px 배수: `4 8 12 16 24 32 48 64`. 페이지 거터 `clamp(16px, 5vw, 48px)`, 최대 폭 1120px.
- 반지름: 카드 20 / 입력 12 / 칩·필 999.
- 그림자 없음(헤어라인 1px + 호버 시 `--ink` 보더). 모달/토스트만 `0 8px 24px rgba(0,0,0,.12)`.
- 터치 타깃 ≥ 44×44px, 입력 높이 52px.

### 2.4 모션
- 전환 150~200ms ease, 결과 숫자 변화는 **카운트 애니메이션 없이** 즉시(정확성 우선).
- `prefers-reduced-motion: reduce` 에서 모든 transform/transition 제거.

```

┌ 입력 카드(5) ──────┐ ┌ 결과 카드(7, sticky) ───────┐   ┌ 입력 카드 ┐
```

- 모바일은 결과가 입력 아래로 흐르고, 결과 카드가 화면 밖일 때 하단 고정바에 월 실수령 요약을 표시(탭하면 결과로 스크롤). 결과 카드가 보이면 고정바 숨김(IntersectionObserver).
- 결과 영역 `aria-live="polite"`: 값이 바뀌면 "월 실수령액 3,2xx,xxx원" 낭독.

| 계산기 | 입력 카드 | 결과 카드 |

| 연봉 | 위 와이어 | 히어로 + SplitBar + 공제표 + (토글) 사업주 부담 |

| 4대보험 | 월 보수·기준일·규모·산재율 | 표: 보험별 [총액 / 근로자 / 사업주], 합계, 상·하한 배지 |
| 연말정산 | 탭 2개(내 예측/부부 비교; 부부 탭은 각자 "소득 유형" 근로/프리랜서 전환 — `data-when` 으로 입력 묶음 교체). 섹션(`details.more`): 카드·의료교육보험·기부금·연금주택월세·직접 입력. 부양가족 행(`.dep-row`: 관계·출생연도·소득요건·삭제 + 가족별 지출 칸, 최대 6) | 히어로(환급/추가 납부) + 단계표 + 절세 팁. 부부 탭: 배분별 세금 비교표 + 가족별 "반대로 하면 +얼마" 목록 + 공동 카드 추천 |
| 프리랜서 | 탭 3개 | A: 세전/실수령 + 3.3% 분해 / B: 단계표(수입→경비→소득→과세표준→세액→정산) 워터폴 형태 / C: 월 실수령 종합 |

### 4.4 연봉별 실수령액표 `/salary/table`, `/salary/table/{만원}`
- 인덱스: 표(연봉, 월 실수령, 월 공제) 1,000만~2억, 100만원 단위 스크롤 없는 테이블(모바일은 3열), 행 클릭 → 상세.
- 상세: 해당 연봉의 결과(연봉 계산기와 동일 컴포넌트, 서버 렌더) + 앞뒤 연봉 링크 + FAQ(구조화 데이터).

### 4.5 공유 결과 `/r/{id}`
- 상단 "공유된 계산 결과 · 2026년 기준 · 만료일 YYYY-MM-DD". 결과는 읽기 전용, 버튼 "이 입력으로 다시 계산"(→ 계산기, 쿼리 채움).

### 4.6 계산 기준 `/basis`
- 요율표(표), 공식 요약, 출처 링크, **미확정 항목 목록**(FORMULAS §9), 개정 이력(rate_sets), 원문 보관 파일 링크(R2).

### 4.7 피드백 `/feedback`
- 계산기 선택, "어떤 값이 다른가요?" 텍스트(2,000자), 연락처(선택). 제출 후 "접수되었어요".

### 4.8 404 / 오류
- 대문과 같은 톤 404. 계산기 4개 버튼 제공.

## 6. 접근성 체크리스트
- 모든 입력에 `<label for>`; 도움말·오류는 `aria-describedby`; 오류는 `aria-invalid`.
- 포커스 링 2px `--accent`, offset 3px. 키보드: 탭 순서 = 시각 순서, 세그먼트는 화살표 키.
- 표는 `<th scope>`; SplitBar는 `role="img"` + `aria-label`에 텍스트 요약, 아래 표가 동일 정보 제공.
- 색 대비: 본문 7:1↑, 보조 `--sub` 라이트 5.0:1, 버튼 글자 4.5:1↑.
- 확대 200% / 텍스트 크기 변경에서 레이아웃 깨지지 않음.

## 7. 아이콘·이미지
- 아이콘은 인라인 SVG 최소 사용(화살표, 복사, 다운로드). 래스터 이미지 없음 → 이미지 요청 0.
- `favicon.svg` 대문과 동일 계열(초록 라운드 사각), OG 이미지는 정적 SVG→PNG 1장(`public/og.png`).

## 8. 카피 톤
- 해요체/명사형 혼용 금지: 설명은 **~합니다/~해요 중 "~해요"** 로 통일(대문 톤). 숫자는 단정, 가정은 "가정" 표기.
- 면책: "모의 계산 결과예요. 실제 급여·보험료는 회사와 공단 고지 기준으로 확정돼요."

## 9. 폰트 (적용 완료: Pretendard 다이나믹 서브셋)
개발·QA 를 마친 뒤 마지막 단계에서 **Pretendard 다이나믹 서브셋**(`woff2-dynamic-subset`)으로 전환했다. (대문 사이트와 같은 파일, Pretendard 1.3.9, OFL)
- 파일: 대문 사이트에 있는 `fonts/pretendard.css` + `woff2-dynamic-subset/PretendardVariable.subset.N.woff2` 를 그대로 `public/fonts/` 에 복사 (unicode-range 로 필요한 서브셋만 다운로드).
- CSS: `--font: "Pretendard Variable", system-ui, sans-serif;` 외 다른 웹폰트 로드 금지.
- PDF 생성용은 별도: 서버에서 PDF 내장용 정적 폰트 서브셋 사용 (웹 폰트와 파일이 다름).
- 검증: 네트워크 탭에서 한글 페이지 로드 시 woff2 요청 수·용량, `font-display: swap`, FOUT 시 레이아웃 이동 없음.


## 10. v2 디자인 시스템 (대체됨 — §11 v3 가 현재. 컴포넌트 구조·표 반응형 규칙·검증 항목은 그대로 유효, 색·그림자·그라데이션·도넛·벤토는 폐기)

### 10.1 방향
요즘 금융·생산성 서비스의 흐름을 따른다: **벤토 그리드, 큰 숫자 중심 타이포, 부드러운 그라데이션, 글래스 헤더, 모바일 하단 탭바, 슬라이더 입력, 슬라이딩 세그먼트, 다크 모드 + 수동 테마 토글, 페이지 전환 애니메이션**. 장식은 CSS·인라인 SVG 로만 한다(이미지 요청 0, CSP `style-src 'self'` 준수).

### 10.2 토큰 (`public/css/app.css` `:root`)
| 토큰 | 라이트 | 다크 | 비고 |
|---|---|---|---|

### 10.4 컴포넌트 (추가·변경)
- **홈**: 2단 히어로(카피 + **빠른 계산 카드**: 연봉 입력+슬라이더 → 월 실수령 즉시), 벤토 타일(연봉 큰 타일·급여·4대보험·프리랜서·"법이 바뀌면 계산도 바뀌어요"·"간이세액표 N구간"·자주 찾는 연봉).
- **결과 패널(`r-panel`)**: 배지 + 큰 숫자(최대 3.75rem) + 도넛. 숫자는 값이 바뀔 때 0.35초 따라가고 항상 정확한 값으로 끝난다(`prefers-reduced-motion`·자동화 환경에서는 생략).
- **슬라이더(`.range`)**: 숫자 입력과 양방향 연동(연봉·희망 실수령·기본급·월 보수·수입·금액). 채움 비율은 CSSOM 으로 칠한다.
- **세그먼트**: 슬라이딩 썸(`:has()` 지원 시, 미지원 브라우저는 선택 칸 배경으로 대체).
- **"곧 바뀌는 것"(`details.upcoming`)**: 다음 시행 연도의 확정/확정 전 항목 중 해당 계산기에 영향 있는 것. 접힌 상태에서 건수만 보인다.
- **아이콘**: 인라인 SVG 스프라이트(`<use href="#i-…">`), 장식은 `aria-hidden`.
- **뷰 트랜지션**: `@view-transition { navigation: auto }` (미지원 브라우저는 무시).

### 10.5 표 (반응형 규칙)
| 종류 | 넓은 화면(≥640px) | 좁은 화면(<640px) |
|---|---|---|
| 글이 많은 표 — 계산 기준의 2027 변경·시행예정 개정·미확정 항목·개정 이력 (`.tbl-stack`) | 보통 표. 구분 칸(배지·번호)은 내용 폭(`c-tag`)에 맞춰 한 줄 | **행마다 카드로 쌓음**: 배지+제목 한 줄, 설명은 아래 보조 글자, 짧은 값(날짜 등)은 한 줄에 라벨과 함께 이어 붙음. 머리글은 화면에서만 숨기고 `role` 로 표 의미 유지 |
| 숫자 열이 많은 표 — 요율표·세율표 (`.tbl-wrap`) | 보통 표 | 가로 스크롤 + 표 위에 "옆으로 밀어서 전체를 볼 수 있어요" 안내(`.swipe-hint`). 키보드로도 스크롤(`tabindex=0`) |
| 긴 목록 — 시행예정 개정(약 50건) | 가까운 시행일 8건만 표시, 나머지는 `details` 로 접음 | 같음 |

- 배지(`.badge`, `.tag-*`)는 줄바꿈하지 않는다(`white-space: nowrap`).
- "곧 바뀌는 것" 안내 바(`.upcoming`)는 최대 폭을 두지 않고 아래 입력·결과 영역과 같은 폭으로 맞춘다.
- **iOS Safari**: `input[type=date]` 는 자체 최소 너비·가운데 정렬 때문에 칸 밖으로 나가므로 `appearance:none; min-width:0; max-width:100%; text-align:left` 로 다른 입력칸과 같은 폭에 맞춘다 (실기기 확인 2026-10-11).
- 하단에 "다른 계산기" 링크 묶음을 따로 두지 않는다 (상단 내비·모바일 탭바와 중복).

### 10.6 검증
axe(wcag2a/2aa/21a/21aa) 심각·중대 위반 0 — 라이트·다크 × 데스크톱·모바일 (e2e E21). 키보드: 슬라이더·세그먼트·탭바·토글 모두 포커스 링 표시.
레이아웃 깨짐 방지(e2e E90~E94): 접힌 부분을 모두 펼쳐도 입력칸·표가 자기 칸 밖으로 나가지 않는다, 좁은 화면에서 글 많은 표가 잘리지 않고 배지가 한 줄이다, 안내 바 오른쪽 끝이 결과 영역과 맞는다, 화면에 `${…}`·undefined·NaN 이 보이지 않는다. 문서 전체의 가로 스크롤만 보는 E20 은 칸 안쪽 잘림을 못 잡으므로 둘 다 필요하다.


## 11. v3 디자인 시스템 — "명세서(종이와 잉크)" (폐기됨 — §12 가 현재)

> **폐기 사유(2026-11-07)**: "AI 슬롭 제거"를 장식을 전부 걷어낸 각진 종이·잉크 스타일로 해석했는데, 요즘 흐름(Apple iOS 27 의 다듬은 Liquid Glass)과 반대 방향이고 사용자 의도와도 달랐다. 트렌드를 검색으로 확인하지 않고 기억에 기대 정한 것이 원인이다. 아래 §11.1 의 슬롭 감사 표(무엇을 걷어냈나)는 §12 에서도 그대로 유효하다.

### 11.1 왜 다시 그렸나 (AI 슬롭 감사)
v2 는 2024~25년 "AI 가 만든 핀테크 랜딩"의 공통 문법을 거의 다 갖고 있었다. 감사 결과와 처리:

| v2 요소 | 문제 | v3 처리 |
|---|---|---|
| 초록 → 청록 그라데이션 히어로·결과 패널, 그라데이션 글자 | 어디서나 보이는 기본값. 숫자의 신뢰를 장식이 깎음 | 폐기. 단색 잉크 + 단일 포인트색 |
| 방사형 메시 배경, 글래스(blur) 헤더 | 장식. 가독성 이득 없음 | 단색 종이 배경, 1px 먹줄 헤더 |
| 벤토 타일 그리드(크기만 다른 둥근 카드) | 정보 위계가 아니라 모양으로 채움 | 번호 붙은 **목차(.index)** 한 열 |
| 카드 반지름 24·알약 버튼 999, 큰 그림자 | 부풀린 느낌 | 반지름 2px, 그림자 없음, 1px 괘선 |
| 도넛 차트, 슬라이딩 세그먼트 썸, 숫자 카운트 애니메이션 | 장식 모션·정보 중복(막대·표가 이미 있음) | 도넛 제거, 선택 칸은 먹색 채움, 모션 최소 |
| 탭바 아이콘, ✨ 류 아이콘, 이모지 느낌 배지 | 의미 없는 아이콘 | 글자만 있는 탭바, 아이콘은 테마·공유·내보내기·깃발 7개만 |
| "~해보세요!" 식 들뜬 카피 | 금융 도구에 맞지 않는 톤 | 사실 문장 위주(해요체 유지), 법령 확인일·기준일을 첫 줄에 |

### 11.2 조사한 흐름과 반영
- **편집 디자인(editorial)·타이포 중심**: 큰 제목·큰 숫자 자체를 그래픽으로 쓴다 → 결과 숫자 `clamp(2.75rem, 11vw, 5rem)`, 제목 자간 -0.04em.
- **반(反)글래스·플랫 회귀 / 뉴브루탈리즘의 절제판**: 선명한 1px 윤곽, 큰 그림자 없음 → 괘선·2px 반지름.
- **따뜻한 종이 톤 + 단일 포인트색**: 순백·순흑 대신 종이(`#f4f1e8`)·잉크(`#1a1915`), 포인트는 잉크 블루 한 색.
- **데이터 문서 문법**: 회계 장부의 이중 밑줄(합계), 점선 리더(범례), 탭풀 숫자(`tabular-nums`) → "계산서" 느낌.
- **다크 모드는 반전이 아니라 같은 종이의 밤 버전**: 종이 `#13120f`, 잉크 `#ece8da`, 포인트 `#8fb0ff`.
- (조사는 공개된 디자인 동향 기사·사례 위주이며 특정 서비스의 시각 자산을 가져오지 않았다.)

### 11.3 단일 방향: 명세서
급여명세서·세금계산서처럼 **숫자가 주인공이고, 근거가 항목 옆에 붙는** 화면. 모든 결정은 "명세서 같은가"로 판단한다.

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `--paper` (배경) | `#f4f1e8` | `#13120f` |
| `--ink` (글자·버튼 채움) | `#1a1915` | `#ece8da` |
| `--accent` (링크·강조·현재 위치) | `#1b3a8c` | `#8fb0ff` |
| `--rule` (괘선) | 잉크 18% 투명도 | 잉크 20% |
| `--r` | 2px | 2px |
| `--seg-1..6` | 분할 막대 단색 6단계(명도 차) | 〃 |

- 강조는 색이 아니라 **두께**(3px 상단선, 이중 밑줄)와 **크기**로 한다. 색 의미는 안내(`.notice`: "안내/주의" 글자 라벨을 `::before` 로 붙여 색에만 의존하지 않음)와 `--danger` 뿐.
- 결과 패널(`.r-panel`): 3px 상단선 + 큰 숫자 + 한 줄 부연. 배지는 사각 윤곽.
- 표(`.tbl`): 머리글 아래 괘선, 합계(`tfoot`) 3px 이중선. 숫자 열은 오른쪽 정렬·탭풀.
- 모바일: 탭바는 전폭 글자만(현재 항목 3px 포인트 막대), 요약바는 전폭 먹색 띠.
- 인쇄(`@media print`): 결과 영역만, 흑백, 괘선 유지 — 명세서로 출력해도 쓸 만하다.
- 허용한 예외: 슬라이더 채움·select 화살표의 `linear-gradient`(기능 목적).

### 11.4 지키는 법 (자동 검사: `tests/core/design-guard.test.ts`)

## 12. v4 디자인 시스템 — "Liquid" (현재)

### 12.1 방향과 근거
Apple 이 WWDC26 에서 낸 iOS 27 은 Liquid Glass 를 버리지 않고 **다듬었다**. 2026-11-07 에 검색해 확인한 내용([designfornative](https://designfornative.com/what-designers-need-to-know-about-ios-27/), [TechTimes](https://www.techtimes.com/articles/317975/20260608/apple-liquid-glass-ios-27-wwdc-2026-brings-refinements-developers-must-adopt-today.htm), [Cult of Mac](https://www.cultofmac.com/news/liquid-glass-changes-ios-27-macos-27) 등 보도와 개발자 베타 분석):
- 시스템 전반의 **투명도 강도 슬라이더** (iOS 26 은 켜기/끄기뿐이라 가독성 불만이 컸다).
- 유리가 **번지는 그림자 대신 더 또렷한 테두리**로 구분된다. 다크 모드의 유리는 더 밝아지고, 탭바의 선택 항목 배경은 더 어두워졌다.
- 컬러 버튼 라벨 **대비 개선**(노랑·주황 위 라벨 문제 해결). 스크롤 가장자리 효과 기본값이 부드러운 그라데이션에서 hard 블러 + 하단 테두리로.
- 탭바는 검색만 따로 떼지 않고 모든 탭을 같은 탭바 안에 둔다.
- (확인 못 한 것: 모서리 반경·모션의 구체 규칙. Apple HIG·WWDC 세션 원문은 이번에 읽지 못했다.)

웹으로 옮기는 원칙 — 이것이 "슬롭 없는 Liquid Glass"의 조건이다:
1. **유리는 내비게이션 층에만** (헤더·하단 탭바·모바일 요약바). 내용은 유리가 아니라 둥근 **그룹 카드**(불투명 면) 위에 둔다. 내용까지 유리로 만들면 가독성이 무너진다(iOS 26 의 불만).
2. **그림자 없음, 또렷한 1px 테두리 + 안쪽 상단 하이라이트**만.
3. **투명도를 사용자가 줄일 수 있다**: `prefers-reduced-transparency`(iOS 27 슬라이더에 해당)·`prefers-contrast: more`·`backdrop-filter` 미지원에서는 유리를 걷어내고 불투명 면으로.
4. 반지름은 **동심 체계**(§12.3) 하나. 임의 px 금지.
5. 색은 파랑 하나(시스템 파랑 계열을 AA 대비로 어둡게) + 회색 단계. 보라·그라데이션·메시·벤토·장식 아이콘은 §11.1 감사대로 계속 금지.
6. 모션은 짧은 `transition`(색·눌림 scale .98)만. 키프레임·튀는 이징·호버 떠오름 금지. `prefers-reduced-motion` 에서는 모두 끈다.

### 12.2 토큰 (`public/css/app.css` `:root`)
| 토큰 | 라이트 | 다크 | 비고 |

### 12.3 모서리 (동심 체계)
`--r-xs 10` ⊂ `--r-s 14`(입력·세그먼트 트랙: 안쪽 칸 10 + 여백 4) · `--r-m 20`(결과 패널·안내·알림: 카드 28 − 여백 8) · `--r-l 28`(카드·그룹 목록) · `--r-pill 999`(버튼·탭바·칩·스위치). `border-radius` 에는 이 토큰과 0·50% 만 쓴다.

### 12.4 컴포넌트
- **헤더**: 유리 + 하단 헤어라인, 데스크톱 내비는 회색 트랙 안의 알약(현재 항목은 흰 알약). 테마 버튼은 회색 원.
- **하단 탭바(<760px)**: 화면 아래 12px 위에 뜨는 유리 알약, 선택 항목은 알약 안의 알약 + 파랑 글자. 글자만(아이콘 없음). 요약바는 그 위에 뜨는 유리 알약 + 파란 "자세히" 버튼.
- **카드·그룹 목록**: 불투명 `--sheet` + 1px 테두리 + 28px. 홈 계산기 목록·FAQ 는 설정 앱처럼 한 카드 안의 행(헤어라인 구분).
- **결과 패널**: 카드 안에 파란 틴트 패널(20px), 큰 숫자(최대 4.75rem, 800), 분할 막대는 알약, 범례는 원형 점.
- **입력**: 회색 채움 입력칸(14px), 포커스 시 흰 면 + 파란 안쪽 링. 슬라이더는 6px 줄 + 흰 원 손잡이. 세그먼트는 회색 트랙 + 선택 칸만 흰 면. 체크는 **스위치**. 스테퍼는 원형 ± 버튼.
- **버튼**: 기본 회색 알약, 주 행동은 파란 알약, 눌림 scale .98.
- **표**: 헤어라인, 합계 행 위 1px 잉크선. 글 많은 표의 모바일 카드화 규칙은 §10.5 그대로.
- 인쇄: 결과만, 유리·틴트 없이 흰 종이(테마 토큰을 라이트로 고정).

### 12.6 검증 기록 (2026-11-07)
Chromium 라이트·다크 × 390·768·1280px 로 홈·연봉·연말정산·프리랜서·계산 기준 확인. 내비·탭바 전환 폭은 800px(760~799px 에서 알약 내비가 테마 버튼을 찌그러뜨렸다). e2e 181 통과(axe 라이트/다크 포함 — 다크 탭바 라벨 대비 위반을 `--glass-sub` 로 해결). **WebKit(iOS Safari)은 이 환경에 없어 미확인**: `-webkit-backdrop-filter`, 하단 탭바 ↔ 홈 인디케이터 간격, 스위치(`appearance:none` + `::after`), `input[type=date]` 는 실기기 확인이 필요하다.
