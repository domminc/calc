# QA 계획서 · 통합 테스트 시나리오

> 대상: homesell 계산기 v0.1 (2026년 기준) · 작성 2026-10-10
> 관련: [기획서](PLANNING.md) · [계산식](FORMULAS.md) · [플로우](FLOWS.md) · [디자인](DESIGN.md)

## 1. 목적과 범위
- **목적**: ① 계산 결과가 공식 기준(간이세액표·공단 예시·법령)과 일치하는지 ② 입력→결과→공유/내려받기 흐름이 끊기지 않는지 ③ 접근성·보안·성능이 기준을 넘는지 확인한다.
- **범위**: 연봉·급여·4대보험·프리랜서 계산기, 연봉표(SEO), 계산 기준 페이지, 공유 링크(DB), 내려받기(R2), 신고(DB), 예약 작업, 보안 헤더.
- **범위 밖**: 연말정산, 일용직·외국인, 두루누리, 기준경비율(기획서 §4 "v1 제외").

## 3. 테스트 전략

| 레벨 | 도구 | 위치 | 대상 |
|---|---|---|---|

| e2e | Playwright(Chromium, 데스크톱+모바일) + 로컬 Worker(workerd) + 임시 Postgres | `tests/e2e/*` | 실제 브라우저 흐름, 접근성(axe), JS 없음 |

## 4. 환경
- 로컬/CI: Node 22, Postgres 16(임시, 포트 54330), `wrangler dev --local`(workerd, Hyperdrive→로컬 Postgres, R2 로컬 에뮬레이션), Chromium.
- 시간: 기준일 의존 결과는 `asOf=2026-10-10` 로 고정해 날짜에 흔들리지 않게 한다. Asia/Seoul 시간대.
- 운영 점검(배포 후): `/api/health`, 대표 3개 계산 수동 대조.
