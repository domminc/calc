# QA 계획서 · 통합 테스트 시나리오

> 대상: homesell 계산기 v0.1 (2026년 기준) · 작성 2026-10-10
> 관련: [기획서](PLANNING.md) · [계산식](FORMULAS.md) · [플로우](FLOWS.md) · [디자인](DESIGN.md)

## 1. 목적과 범위
- **목적**: ① 계산 결과가 공식 기준(간이세액표·공단 예시·법령)과 일치하는지 ② 입력→결과→공유/내려받기 흐름이 끊기지 않는지 ③ 접근성·보안·성능이 기준을 넘는지 확인한다.
- **범위**: 연봉·급여·4대보험·프리랜서 계산기, 연봉표(SEO), 계산 기준 페이지, 공유 링크(DB), 내려받기(R2), 신고(DB), 예약 작업, 보안 헤더.
- **범위 밖**: 연말정산, 일용직·외국인, 두루누리, 기준경비율(기획서 §4 "v1 제외").

## 3. 테스트 전략

| 레벨 | 도구 | 위치 | 대상 |
|---|---|---|---|
| 단위·골든 | Vitest | `tests/core/*` | 계산 코어(식·경계·단조성·역산) |
| 서버 스모크 | Vitest + Hono `app.request` | `tests/server/*` | 모든 페이지 200·헤더·404·health·DB 없음 동작 |
| DB 통합 | Vitest + 임시 Postgres | `tests/db/*` | 마이그레이션(멱등)·공유·신고·제한·통계·내보내기 캐시·예약 삭제 |
| e2e | Playwright(Chromium, 데스크톱+모바일) + 로컬 Worker(workerd) + 임시 Postgres | `tests/e2e/*` | 실제 브라우저 흐름, 접근성(axe), JS 없음 |
| 정적 | TypeScript strict · ESLint | CI | 타입·품질 |
| 수동 | 체크리스트 §9 | — | 실기기·호환·인쇄·PDF 열람 |
| UAT | 실제 명세서·고지서 §10 | — | 미확정 단수처리 확정 |

CI(`.github/workflows/ci.yml`)가 PR 마다 위를 모두 실행한다. 배포 워크플로는 단위+타입+린트+마이그레이션 후 배포한다.

## 4. 환경
- 로컬/CI: Node 22, Postgres 16(임시, 포트 54330), `wrangler dev --local`(workerd, Hyperdrive→로컬 Postgres, R2 로컬 에뮬레이션), Chromium.
- 시간: 기준일 의존 결과는 `asOf=2026-10-10` 로 고정해 날짜에 흔들리지 않게 한다. Asia/Seoul 시간대.
- 운영 점검(배포 후): `/api/health`, 대표 3개 계산 수동 대조.

## 10. 실사용 대조(UAT) — 미확정 U1~U8 확정
공식 원문으로 확인하지 못한 단수처리 등은 **실제 문서**로 확정한다 ([FORMULAS §9](FORMULAS.md)).

| 필요한 자료 | 대조 대상 | 확정되는 항목 |
|---|---|---|
| 실제 월급명세서 3건(서로 다른 월급 수준) | 국민연금·건강보험·장기요양·고용보험·소득세·지방소득세 각 항목 | U1, U2, U3, U8 |
| 사회보험통합징수포털 고지내역 1건 | 건강보험·장기요양 근로자 부담 | U2, U7 |
| 사업장 산재 요율(근로복지공단 확정통지) | 사업주 부담 | U4 |
| 3.3% 원천징수 영수증(소득 지급 금액이 1원 단위인 건) | 소득세·지방소득세 | U5 |
| 홈택스 경비율 조회 캡처(본인 업종코드) | 단순경비율 | U6 |

대조 방법: 같은 입력으로 계산기를 돌려 항목별 차이를 표로 기록 → 차이가 있으면 `rates.json`·식을 고치고 골든 벡터에 추가 → `verified:true` 로 갱신 → `/basis` 목록에서 제거.
